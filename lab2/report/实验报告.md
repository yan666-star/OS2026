## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本章围绕物理内存管理展开，主要解决内核如何识别可用内存、记录物理页状态，以及按需分配和回收连续物理页的问题。

实验以已有的 Sv39 启动页表为运行基础，先从设备树获取物理内存范围，再使用 Page 描述符记录各个物理页的状态。扣除 OpenSBI、内核镜像和描述符数组占用的空间后，将剩余完整页面交给物理内存管理器管理。在此基础上，学习和实现不同的页面分配算法，并通过测试检查分配、释放和空闲块合并是否正确。

### 2.2 功能的逐步实现

1. 理解启动页表与地址转换关系。
首先理解框架如何建立启动页表、设置 satp 并进入虚拟地址空间。内存初始化代码已经运行在分页模式下，因此必须先区分虚拟地址、物理地址和物理页号，才能正确计算内核及管理数据占用的空间。

2. 完成物理内存探测和页描述符初始化。
根据设备树提供的内存基址与大小确定管理范围，由 `page_init()` 建立描述符数组，保留已占用页面，并将完整空闲页注册到已初始化的内存管理器中。这一步为后续页面分配提供初始资源。

3. 理解框架提供的 First-Fit 算法。
阅读其初始化、分配和释放流程，理解空闲链表、空闲块拆分及相邻块合并的实现。先掌握完整的参考实现，有助于理解 `pmm_manager` 各接口之间的协作关系。

4. 实现并接入 Best-Fit 算法。
在理解 First-Fit 的基础上，将分配策略调整为选择满足请求的最小空闲块，并完成拆分、回收和合并。实现后切换当前管理器，通过框架自检验证实际运行的是 Best-Fit。

5. 实现 Buddy System 并设计测试。
进一步采用按二的幂划分内存块的方式管理页面，理解伙伴块的拆分与合并。分别设计实现提示词和测试提示词，检查分配、回收、边界条件及资源耗尽等情况。

6. 通过 GDB 观察地址翻译过程。
在理解页表和物理页管理后，调试 QEMU 中的 TLB 查询与页表遍历过程，将内核中的地址转换概念与模拟器执行流程联系起来，加深对软硬件协作方式的理解。

### 功能模块一：物理内存初始化功能

**负责人：** 2413777-施骅洋

#### 模块功能描述

**需要实现/修改的函数：**

```c
static void page_init(void); (kern/mm/pmm.c)
```

**功能说明：**

`pmm.c` 是内核物理内存管理的统一入口，负责建立物理页的管理信息，并为其他模块提供页面分配与回收接口。

- **系统中的作用：** 初始化物理内存管理器，通过 `page_init()` 建立 `Page` 描述符数组，并提供 `alloc_pages()`、`free_pages()` 和 `nr_free_pages()` 等接口。
- **主要处理场景：** 获取并校验物理内存范围，处理管理上界和页面对齐，排除 OpenSBI、内核镜像及描述符数组占用的页面，将剩余完整空闲页交给分配器管理。
- **与其他模块的交互：** 从设备树模块读取内存信息，使用 `memlayout.h`、`pmm.h` 等提供的布局与地址转换定义，通过 `pmm_manager` 调用具体分配算法，并在初始化后执行分配器自检。

````markdown
4. **布局描述符并保留已用页面。**  
   将描述符数组放在 `end` 之后并按页对齐。写入前确认内核镜像及整个数组都位于有效管理范围内，空间不足时终止。初始化所有描述符并标记为 reserved，确保 OpenSBI、内核镜像、描述符数组及对齐填充占用的页面不会进入空闲区。

5. **仅注册完整空闲页。**
````

#### 模块功能描述

**需要实现/修改的函数及注册结构：**

```c
// kern/mm/pmm.c：仅修改该函数内的管理器选择

```

**功能说明：**

本模块在任务一已建立页描述符和可用物理页范围的基础上，负责连续物理页的分配与回收。参考完整的 First-Fit 实现，保留原有页面描述符和链表语义，将分配策略改为选择“能满足请求且页数最少”的空闲块。

- **内部状态：** 使用 `static free_area_t free_area`，以 `free_list` 表示空闲块链表、`nr_free` 表示空闲页总数。链表按地址递增排列，只有空闲块首页设置 `PageProperty`，其 `property` 记录连续页数。该状态符合原测试直接保存、清空和恢复链表及计数的约定。
- **初始化：** `best_fit_init()` 建立空链表；`best_fit_init_memmap()` 清理可用页面的保留标志、块属性和引用计数，登记空闲区域，增加空闲页数，并合并相邻区域。
- **分配：** `best_fit_alloc_pages(n)` 扫描候选块，选择最小可用块；同样大小时选择低地址块，遇到恰好匹配时提前结束。从块首分配恰好 n 页，剩余部分仍作为空闲块留在原位置。总空闲页不足或不存在足够大的连续块时返回 `NULL`，不改变状态。
- **释放：** `best_fit_free_pages()` 重置待释放页的状态和引用计数，增加空闲页数，再由 `best_fit_insert_block()` 按地址插入并合并前后相邻块。合并只改变块边界，不重复增加空闲页总数。
- **注册与接入：** 根据 `pmm.h` 的 `struct pmm_manager` 定义 `best_fit_pmm_manager`，注册初始化、分配、释放、统计和原检查函数；在 `init_pmm_manager()` 中将指针改为 `&best_fit_pmm_manager`，使统一分配接口调用 Best-Fit。

例如，按地址排列的空闲块为 10、6、8 页，申请 4 页时选择 6 页块，分出前 4 页并留下 2 页。这体现了 Best-Fit 选择最小可用块的策略。

**功能说明：**

本模块在任务一（页描述符与空闲页范围）和任务二（Best-Fit）的基础上，实现按 2 的幂划分内存块的 Buddy System 分配器，并编写可在真实内核中运行的单元测试。

- **在整个系统中的作用：** 作为 `struct pmm_manager` 的第三种实现（`buddy_pmm_manager`），与 `default_pmm_manager`、`best_fit_pmm_manager` 并列。`pmm.c` 仍注册 Best-Fit 作为内核实际使用的分配器，伙伴系统通过 `buddy_pmm_manager` 被测试以黑盒方式驱动，二者互不干扰。
- **块组织：** 共 16 阶（order 0..15），第 k 阶块大小为 2^k 页，最大块 2^15 页 = 128MiB，足以覆盖本实验约 126MB 的可用内存。每阶一条按地址升序排列的空闲块链表，空闲页总数 `nr_free` 单独记录，不与“块个数”混用。
- **伙伴计算方式：** 采用“相对区域基址（region base）的页偏移”，第 k 阶块的伙伴偏移为 `offset ^ 2^k`。所有对齐判断、伙伴推导都只依赖相对偏移，不依赖描述符在 `pages` 数组中的绝对下标，因此测试可以把一块独立的静态 `struct Page` 数组当作 arena 反复 init/init_memmap，用例之间完全隔离。
- **分配流程：** 取 k = ceil(log2(n))，从 k 阶向上找到第一个非空阶，取出块后逐级对半拆分，把高半块挂到对应阶，交付方恰好得到 n 页。
- **尾页归还：** 请求 n 页而实际取出 2^k 页时，多出的 [n, 2^k) 尾页不交付调用方，而是按“尽量大且对齐”的贪心规则拆成 2 的幂块重新挂回链表并参与合并，因此 `nr_free` 恰好只减少 n。
- **释放与合并：** 释放区间同样按贪心规则拆块插入，每块插入后逐级向上与伙伴合并，伙伴必须恰为同阶空闲块的首页；若自身是右半块，则把 `property` 与 `PageProperty` 转移到地址较小的伙伴上，避免合并后的新块内部页残留首页标志。
- **不变式与自检：** `buddy_verify_free_lists()` 校验 I1（第 k 阶块首页标志与块长匹配、内部页无标志）、I2（相对基址偏移按自身大小对齐）、I3（空闲块互不相交）、I4（各阶页数之和等于 `nr_free`）、I5（交付页均非保留、非空闲块首页）、I6（`nr_free` 不超过区域总页数）；`buddy_check()` 在此基础上做分配/释放往返验证，并在结束时断言状态与进入前完全一致。
- **与其他模块的交互：** 只使用 `memlayout.h`、`pmm.h` 提供的 `struct Page`、页标志宏，以及 `libs/list.h` 的链表操作；测试入口只调用 `buddy_pmm_manager` 的成员函数指针，不修改全局 `pmm_manager`，对真实物理内存管理器零副作用。

````markdown
## S3. buddy_alloc_pages(size_t n)
````

### Challenge：硬件的可用物理内存范围的获取方法

**负责人：** 2413777-施骅洋

如果操作系统无法提前知道硬件的可用物理内存范围，可以在启动时从固件或引导程序提供的信息中获取，而不必将内存起始地址和大小写死在代码中。

本实验采用设备树来描述硬件信息。启动环境通过 `a1` 寄存器将设备树的物理地址传给内核，内核解析其中的内存节点，得到 RAM 的起始地址和长度。这样，即使内存大小发生变化，内核也可以根据实际信息进行初始化。其他启动环境也有类似机制，例如 UEFI 可以通过 `GetMemoryMap()` 提供包含地址、大小和类型的内存映射表。获取 RAM 范围后，还需要排除固件、内核及管理数据占用的区域，才能确定真正可供分配的物理内存。

### 练习：理解first-fit 连续物理内存分配算法

**负责人：** 2413777-施骅洋

First-Fit 分配器使用按物理地址递增排列的空闲链表，每个节点代表一个连续空闲块，块首页的 `property` 记录页数，`nr_free` 记录空闲页总数。

- **初始化：** `default_init()` 初始化空闲链表并清零空闲页计数；`default_init_memmap()` 清除指定页面的保留标志，初始化属性和引用计数，设置空闲块首页及块大小，再按地址顺序加入链表。
- **分配：** `default_alloc_pages(n)` 从链表头查找第一个不少于 `n` 页的空闲块，分配其前 `n` 页。若有剩余，则将剩余部分作为新空闲块留在链表中，并更新标志和空闲页总数。若找不到足够大的连续块，则返回 `NULL`。
- **回收和合并：** `default_free_pages()` 重置待释放页面的状态，将其组成空闲块并按地址插回链表，再检查它与前后空闲块是否物理连续；若连续，则合并块大小并删除多余节点。合并不改变空闲页总数。

**First-Fit 仍有改进空间。** 当前顺序查找的最坏时间复杂度为 `O(m)`，其中 `m` 为空闲块数，可通过增加索引提高查找效率；也可以改用 Next-Fit，减少反复扫描链表前部，但这会改变分配策略。现有代码已经实现释放时的相邻块合并，不过仍无法消除被已分配页面隔开的外部碎片。若初始化时分多次登记相邻区域，也可以增加合并操作，提高连续空闲内存的利用率。


### 练习：Best-Fit 算法是否有进一步的改进空间

**负责人：** 2411641-薛健

**有。** 当前实现使用空闲链表，设空闲块数为 m，分配和释放时查找块的最坏时间复杂度为 `O(m)`，定位后的相邻块合并为 `O(1)`。释放 n 页还需 `O(n)` 重置页描述符，新增管理状态为 `O(1)`。

可以从以下方面改进：

1. **提高查找效率。** 按“块大小、起始地址”建立平衡搜索树，通过下界查询在 `O(log m)` 时间内找到最小可用块。配合地址索引或边界信息定位相邻块，并在拆分、合并时同步更新索引。
2. **为常见请求分组。** 按请求页数建立大小分组，结合非空位图缩小搜索范围，在候选组中选择满足请求的最小块，保持 Best-Fit 的分配规则。
3. **评估外部碎片。** Best-Fit 容易留下较小的空闲块，可统计空闲块数量、最大连续空闲块和分配失败率，结合实际负载评估效果。释放时及时合并相邻块，有助于恢复较大的连续空闲区域。

**功能说明：**

在已有物理页分配器之上，实现 SLUB 风格的“任意大小内存单元”分配器，把“页”这一层与“对象”这一层显式分开。

- **两层架构：** 第一层是已有的页分配器（`best_fit_pmm_manager` 注册的 `alloc_pages()`/`free_pages()`），SLUB 只通过它申请/归还整页，绝不绕过；第二层是本模块，把整页按对象大小分档切成等长对象，每档一个 cache，cache 用 slab 链表管理对象。
- **内嵌空闲链表：** 空闲对象的头 8 字节存放下一个空闲对象的指针，分配是 `O(1)` 摘链、释放是 `O(1)` 头插，不额外消耗内存。
- **档次划分：** 对象大小为 2 的幂，从 8 字节到 2048 字节共 9 档；每个 slab 恰好占 1 个物理页；请求大小向上取整到“覆盖它的最小档”（1→8，100→128，2000→2048），用户可见大小始终不小于请求大小。
- **大对象直通：** 超过 2048 字节的请求不做对象切分，直接调用 `alloc_pages(ceil(size/PGSIZE))`，返回页对齐地址，并登记到静态大对象表中。
- **元数据布局：** slab 元数据（所属 cache、宿主页、内嵌链表头、已用对象数、对象总数、已分配位图、链表节点）全部放在本模块的静态结构体池中；大对象表记录宿主页、页数与请求大小。没有给 `struct Page` 增加任何字段，也不复用 `property`/`ref`。
- **失败语义：** 第一层无页、slab 元数据池耗尽、大对象表满时，返回 NULL。
- **地址换算与交互：** 页→可写内核虚址使用 `page2pa(page) + va_pa_offset`；对象→`struct Page` 使用 `pa2page(PADDR(obj))`。`pmm.h` 中的 `KADDR` 已被注释，因此在 `slub.c` 内定义 static inline 辅助函数代替，不修改任何头文件。

**档次表与每页对象数：**

| 档下标 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|--------|---|---|---|---|---|---|---|---|---|
| 对象大小（字节） | 8 | 16 | 32 | 64 | 128 | 256 | 512 | 1024 | 2048 |
| 每页对象数 | 512 | 256 | 128 | 64 | 32 | 16 | 8 | 4 | 2 |

**必须成立的不变式：** 每个 slab 恰为 1 页且来自 `alloc_pages(1)`；同一 slab 内对象等长且不跨页；任意两个已分配对象区间不相交；已用对象数降为 0 时立即 `free_pages()` 归还并把元数据槽还给静态池（空 slab 不驻留）；大对象占用连续页且返回页对齐地址；失败零副作用；返回地址至少 8 字节对齐（档路径按档大小对齐）；已分配的对象内容不会再被后续分配和覆写。

````markdown
        不同档的对象不可能落在同一页（用 (uintptr_t)ptr & ~(PGSIZE-1) 分组，
        断言同一页只出现一个档的对象）；
        各档 slub_objects_of_class 计数正确；
        全部释放后 nr_free_pages() == base_free。

--- T5 对象内容不被覆写（写穿检测） ---
  步骤：分配 200 个随机档对象，按 seed 填满整个 [ptr, ptr+size) 区间；
        再分配/释放一批其它对象（制造内存复用压力）；
        最后逐个回读 200 个对象的 pattern。
  断言：全部回读一致；期间无对象区间重叠；
        （若不一致，说明某次分配把仍在用的对象内存发了出去。）

--- T6 大对象直通 ---
  步骤：覆盖 size = 最大档+1、4096、4097、10000（各一个），写入 pattern 回读。
  断言：返回值 != NULL；
        (uintptr_t)ptr % PGSIZE == 0（页对齐，C5）；
        与所有小对象、其它大对象区间不重叠；
        pattern 一致；
        slub_large_count() 等于当前存活大对象数；
        全部 kfree 后 slub_large_count() == 0 且 nr_free_pages() == base_free。

--- T7 分配失败与零副作用（尽力而为） ---
  步骤：构造一次"极大"请求（例如 size 大于可用物理内存页数 * PGSIZE，
        或 > 128MB），调用 kmalloc。
  断言：返回 NULL（若第一层仍能满足，则本用例改为 SKIP 并打印
        `[SLUB Test] T7 alloc-fail: SKIP (first layer still has memory)`）；
        返回 NULL 时：各档 slab 数/对象数、slub_large_count()、
        nr_free_pages() 与调用前完全相同（C8）。

--- T8 随机压力测试（确定性） ---
  步骤：固定 seed = 20241023 的 LCG，循环 2000 轮；每轮随机选择：
          分配：size 在 [1, 5000] 随机（另加若干固定值 1/8/64/2048/4097）；
          释放：从存活记录中随机取一条；
        每次分配成功后：登记区间（重叠检测）、fill_pattern、
        slub_objects_of_class / slub_large_count 计数校验；
        每次释放前：check_pattern 必须一致、区间必须处于存活状态；
        每 200 轮：打印一次 slub_dump()，并校验
            "存活对象的档计数 == 影子记录按档统计的值"。
  断言：全程无区间重叠、无 pattern 损坏、无计数漂移；
        结束释放全部记录后：slub_large_count() == 0、
        各档 objects/slabs 均为 0、nr_free_pages() == base_free。

--- T9 零副作用 ---
  断言：slub_test 结束时 pmm_manager == &best_fit_pmm_manager；
        nr_free_pages() == 进入测试时的值；
        （可选）结尾调用一次 slub_dump() 打印最终统计。
````

#### 实现迭代过程

本模块经历了 **4 次迭代**：实现、接入、编写单元测试（其间暴露并修正一处测试自身缺陷）、整体回归。

##### 第一次迭代：实现两层 SLUB 分配器

对应文件：`kern/mm/slub.c`、`kern/mm/slub.h`

**实现过程：**

1. 在 `slub.c` 顶部用注释明确标出**对第一层的全部调用点**：新建 slab 的 `alloc_pages(1)`、大对象直通的 `alloc_pages(npages)`、以及 `kfree()` 中的 `free_pages(page, n)`；其余代码一律不触碰页分配器内部。
2. 定义三类静态元数据：`slub_caches[9]`（每档 partial/full 两条链、档大小、每页对象数、slab 数与已用对象数）、`slub_slab_pool[256]`（slab 元数据池，含 512 bit 已分配位图）、`slub_large_tab[128]`（大对象登记表）。
3. 内嵌空闲链表由两个 `static inline` 函数完成：`slub_freelist_push` 把对象头 8 字节写成当前链头，`slub_freelist_pop` 读回 next 并更新链头，均为 O(1)。
4. 新建 slab 时倒序头插建链（使链头是页内第 0 个对象），对象偏移为 `i * 档大小`，满足不跨页与按档对齐。
5. 大对象路径先检查表容量再 `alloc_pages`，成功后在表中登记；反查时按宿主页匹配，保证失败零副作用。

**遇到的问题：**

一是 `kfree` 反查的歧义：大对象基址与小对象所在 slab 的页首都可能是同一个页对齐地址，若先按“地址等于页首”判断，可能把大对象误判成小对象。二是重复释放若靠遍历空闲链表判定，会破坏 O(1) 释放的要求。

**问题解决策略：**

反查顺序改为“先按宿主页匹配大对象表（并校验传入地址必须等于该页基址），未命中再按宿主页匹配 slab 池”；页在任一时刻只属于一个分配者，因此两类路径互斥。重复释放改用每个 slab 一份 512 bit 已分配位图：`kfree` 要求对应 bit 为 1（为 0 说明该对象当前就在空闲链表上），既保持 O(1)，又能立即 `panic` 定位。

##### 第二次迭代：接入 pmm_init 并验证启动日志

**实现过程：**

在 `pmm.c` 中仅增加 `#include <slub.h>` 与 `pmm_init()` 末尾的 `slub_init()`（satp 打印之后）。

**最终结果：**

`make` 零 error 零 warning；`make qemu` 中 `check_alloc_page() succeeded!` 仍正常打印，随后输出 `slub: init done, 9 classes (8b..2048b), slab pool 256, large table 128`、9 行各档统计与一行大对象/第一层空闲页汇总，说明 `slub_init()` 未向第一层要页、期间无 panic。

##### 第三次迭代：编写 T1~T9 单元测试（暴露一处测试自身缺陷）

对应文件：`kern/mm/slub_test.c`、`kern/mm/slub_test.h`

**实现过程：**

1. 影子记录表 `recs[512]` 记录每个存活对象的指针、请求大小、seed、所属档与是否大对象；登记时与所有存活区间两两比对，实现区间互不重叠的校验。
2. `fill_pattern`/`pattern_mismatch` 按 seed 生成确定性字节流，覆盖对象**整个** `[ptr, ptr+size)` 区间，而不是只写头部 8 字节，以便抓到“对象尾部被另一个对象占用”的缺陷。
3. `class_of(size)` 只通过 `slub_class_count()`/`slub_class_size()` 查询，测试中不硬编码档表；对齐检查同时覆盖“8 字节对齐”“按档大小对齐”“大对象页对齐”。
4. T1~T9 依次覆盖：初始化与零分配、各档基本分配、同档批量与 slab 复用、跨档隔离（同页只允许出现一个档）、内容不被覆写（200 个对象 + 扰动）、大对象直通、分配失败零副作用、2000 轮确定性 LCG 压力、全局零副作用。

**遇到的问题：**cd /root/os-lab && git ls-remote origin lab2 | head -1


首轮运行 T3 报 `FAIL (free pages after partial kfree: got=31894 want=31896)`。分析后确认问题出在**测试的期望值**：T3 先分配 100 个 64B 对象（占用 2 页），再释放其中 50 个，此时两个 slab 各自仍有存活对象、页不会被归还，因此 `nr_free_pages()` 的正确期望是“分配 100 个之后的水平”（31896 − 2 = 31894），而不是回到用例基线的 31896。原先直接与 `base_free` 比较，等于把“不回升”误解成“回到基线”。

**问题解决策略：**

在分配完成后记录 `free_after_alloc = nr_free_pages()`，把“部分释放后不回升”的断言改为与 `free_after_alloc` 比较，并在注释中写明准确含义：只释放一部分对象时页仍被 cache 持有，`nr_free_pages()` 保持在分配后的水平；用例结束时全部释放再断言回到 `base_free`。修正后 T3 通过，SLUB 实现本身未做任何修改。

##### 第四次迭代：整体回归

**最终结果：**

- ✅ `make` 零 error 零 warning（`-Wall -Werror -std=gnu99`）
- ✅ `make qemu`：`[SLUB Test] T1~T9` 全部 PASS，末尾打印 `[SLUB Test] ALL PASS`
- ✅ 测试零副作用：结束时 `pmm_manager` 仍为 `best_fit_pmm_manager`，`nr_free_pages()` 回到进入测试时的值
- ✅ `make grade` 仍为 `check page init: OK`、`check best fit: OK`，Total Score: 20/20

**关键改进点总结：**

1. 提示词把“第一层的全部调用点”和“禁止触碰 Page 字段/管理器内部”写成硬边界，避免实现层越界。
2. 用静态位图同时解决“重复释放检测”与“O(1) 释放”的矛盾，并把反查顺序设计成“大对象表 → slab 池”，消除页首地址歧义。
3. 用例必须能区分“实现缺陷”与“测试期望值错误”：T3 的失败最终定位为断言写错，说明每个期望值都应能由契约直接推导。
4. 测试全程使用影子记录 + 整区间 pattern + 计数比对的方法，使一次错误的分配/释放会同时在“重叠、内容、统计”三个维度暴露，方便后续进行错误定位。
