## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本部分围绕线性地址、页表项和物理页的对应关系展开。已有分配器提供可用物理页，多级页表遍历函数定位目标项，本模块在此基础上维护具体映射。

建立映射时，需要处理空项、同页映射和异页映射。撤销映射时，需要清除页表项、刷新地址翻译并减少物理页引用。页表项记录映射，引用计数决定物理页能否回收，TLB 影响处理器实际采用的翻译结果，三者必须保持一致。

### 2.2 功能的逐步实现

1. 核对 Lab2、Lab3 依赖，确认物理页分配、地址转换和 Trap 基础可用。
2. 实现映射建立与替换，区分首次映射、同页权限更新和异页替换。
3. 实现幂等删除，处理页表不存在和目标项无效的情况。
4. 完善中间页表分配失败时的回滚，确保已有状态和空闲页数量正确。
5. 运行页表结构检查和实际访存，定位并修正非叶子项权限问题。

### 功能模块一：虚拟内存页操作功能

**负责人**　2411641-薛健

#### 模块功能描述

**需要实现的函数**

```c
int page_insert(pde_t *pgdir, struct Page *page,
                uintptr_t la, uint32_t perm);
void page_remove(pde_t *pgdir, uintptr_t la);
```

**配套调整的函数**

```c
pte_t *get_pte(pde_t *pgdir, uintptr_t la, bool create);
void tlb_invalidate(pde_t *pgdir, uintptr_t la);
static void check_pgdir(void);
```

**功能说明**

本模块为指定线性地址建立或撤销物理页映射，为后续虚拟内存操作提供基础。实现复用现有页表遍历、物理页分配、页表项构造和引用计数接口。

| 场景 | 映射处理 | 引用计数与资源处理 |
|------|----------|------------------|
| 地址未映射 | 写入目标页及请求权限 | 目标页引用加一 |
| 已映射同一物理页 | 更新权限 | 引用计数不变 |
| 已映射其他物理页 | 替换映射 | 新页引用加一，旧页引用减一，归零时释放 |
| 删除有效映射 | 清空页表项并刷新 TLB | 对应页引用减一，归零时释放 |
| 删除不存在的映射 | 直接返回 | 不分配页表，不修改引用计数 |
| 中间页表分配失败 | 返回 -E_NO_MEM | 回收本次临时页，保留原有状态 |

page_insert 先调用 get_pte(pgdir, la, 1)，失败时直接返回 -E_NO_MEM。成功后检查旧项并取得 old_page。仅在新旧页不同时增加目标页引用，随后使用 pte_create(page2ppn(page), perm) 更新页表项并刷新 TLB，最后减少异页旧映射的引用，归零时释放。新项由本次权限重新构造，旧权限不会遗留。

page_remove 调用 get_pte(pgdir, la, 0) 查询已有映射，目标不存在或无效时返回。存在有效映射时，先保存物理页指针，再清空项、刷新 TLB，最后减少引用并按需释放。重复删除时目标项已经无效，因此不会重复回收。

get_pte 在创建新分支时，先用局部变量保存新分支，等两级中间页表分配成功后再发布根项。第二次分配失败时，释放尚未发布的临时页。非叶子项通过 ptd_create 构造。

tlb_invalidate 使用 sfence.vma 刷新当前 hart 对目标地址的翻译，并在内联汇编中增加 "memory" clobber，约束编译器重排相关内存操作。

#### 实现迭代过程

##### 第一次迭代

**实现内容**

**遇到的问题**

隔离运行中，check_alloc_page 和 check_pgdir 已通过，执行 check_boot_pgdir 中向线性地址 0x100 写入字符串时触发 store_page_fault。QEMU 异常日志的故障地址为 0x100。

**问题解决策略**

**本次结果**

核心源码通过 RISC-V 编译。首次运行通过页表结构检查，实际写入暴露了非叶子项权限问题。

**修改内容**

| 位置 | 修改及目的 |

### 功能模块二：进程创建及初始化功能

**负责人**　2413777-施骅洋

#### 模块功能描述

**需要实现的函数**

```c
static struct proc_struct *alloc_proc(void);
void proc_init(void);
int kernel_thread(int (*fn)(void *), void *arg, uint32_t clone_flags);
int do_fork(uint32_t clone_flags, uintptr_t stack, struct trapframe *tf);
static void copy_thread(struct proc_struct *proc, uintptr_t esp,
                        struct trapframe *tf);
static int copy_mm(uint32_t clone_flags, struct proc_struct *proc);
```

**功能说明**

本模块负责创建、初始化和登记内核线程。当前执行现场被包装为 idleproc，第一个新建内核线程 initproc 通过独立内核栈和首次运行上下文进入进程管理体系，为后续调度提供可运行实体。

| 函数 | 核心处理 | 返回或完成状态 |
|------|----------|----------------|
| alloc_proc | 分配并清零 PCB，初始化状态、PID、内核页表和链表节点 | 成功返回安全空白 PCB，分配失败返回 NULL |
| proc_init | 初始化管理结构，建立 idleproc，再创建和查找 initproc | current 指向 idleproc，initproc 完成登记并处于 PROC_RUNNABLE |
| kernel_thread | 用临时 trapframe 保存函数入口、参数和特权状态 | 返回 do_fork 的 PID 或负错误码 |
| do_fork | 分配 PCB 和内核栈，构造上下文，分配 PID、登记并唤醒 | 成功返回 PID，失败释放已取得的资源 |
| copy_thread | 将 trapframe 放入新内核栈，设置 context 的首次入口及栈指针 | 为 forkret 首次运行链路准备现场 |
| copy_mm | 保留地址空间处理接口，当前阶段直接返回 0 | 维持内核线程共享内核地址空间的约定 |

alloc_proc 使用 kmalloc 分配 PCB，再通过 memset 清零全部字段，使 parent、mm、tf、context、名称、标志位和调度标记等具有确定的初值。随后设置 state = PROC_UNINIT、pid = -1、pgdir = boot_pgdir_pa，并初始化 list_link 和 hash_link。本工程的内核页表字段名为 pgdir。

proc_init 初始化 proc_list 及各哈希桶后，建立 PID 为 0、状态为 PROC_RUNNABLE 的 idleproc。其 kstack 指向已有 bootstack，need_resched 置为 1，current 指向 idleproc。随后调用 kernel_thread 创建 init_main，通过 find_proc 获取 PID 为 1 的 initproc 并设置名称。按框架约定，idleproc 单独管理且计入 nr_process，普通进程链表和哈希表登记新建线程。因此初始化完成时，nr_process 为 2，普通链表和哈希表各登记一个 initproc。

kernel_thread 清零临时 trapframe，以 s0 保存 fn、s1 保存 arg，将 epc 设置为 kernel_thread_entry，并设置 SSTATUS_SPP、SSTATUS_SPIE，清除 SSTATUS_SIE。随后调用 do_fork(clone_flags | CLONE_VM, 0, &tf)。kernel_thread_entry 从 s1 取参数到 a0，再通过 s0 调用 fn(arg)，函数返回后进入已有 do_exit 路径。

copy_thread 将临时 trapframe 拷贝到新线程内核栈顶，并将副本的 a0 设为 0。传入 esp 为 0 时，采用该 trapframe 地址作为初始栈指针，保证内核线程经 __trapret 恢复后具有有效栈。context 按现有结构体布局内嵌于 PCB，其中 ra 指向 forkret，sp 指向新栈上的 trapframe。后续调度通过 switch_to 恢复 context 后，执行 forkret → forkrets → __trapret → kernel_thread_entry，最终调用 fn(arg)。

do_fork 先检查 MAX_PROCESS 上限，再依次申请 PCB、申请内核栈、处理 copy_mm 并构造首次运行现场。所有可能返回错误的资源准备步骤完成后，才在关中断保护下分配 PID、挂接哈希表与进程链表、增加 nr_process，并调用 wakeup_proc。失败时按“已分配的内核栈 → PCB”的顺序释放。由于错误返回发生在 PID 分配与登记之前，失败路径不会遗留链表节点或增加进程计数。

4. **`do_fork`**：检查 `nr_process < MAX_PROCESS`；依次分配 PCB（`alloc_proc`）、分配内核栈（`setup_kstack`）、调用 `copy_mm` 和 `copy_thread`；在 `local_intr_save` / `local_intr_restore` 关中断保护下分配唯一 PID（`get_pid`）、加入 `hash_list` 和 `proc_list` 并递增 `nr_process`；调用 `wakeup_proc` 唤醒新线程并返回 PID。任一步骤失败必须按逆序完整回滚（释放内核栈、释放 PCB），确保无内存泄漏和悬挂链表节点，返回负错误码（如 `-E_NO_MEM`、`-E_NO_FREE_PROC`）。
5. **`copy_thread`**：在新线程内核栈顶放置 `struct trapframe`（`proc->tf`）并拷贝 `tf` 内容，清零 `tf->gpr.a0`（子进程返回值为 0）并设置 `tf->gpr.sp = esp`；初始化 `proc->context`，使 `ra = (uintptr_t)forkret`、`sp = (uintptr_t)(proc->tf)`，与 `forkret -> forkrets -> __trapret` 首次运行链路正确衔接。
6. **`copy_mm`**：当前实验阶段不做用户地址空间复制，保持接口形态完整并直接返回 `0`。

## 六、实验总结与收获

### 对操作系统的理解

#### 1. 本实验的重要知识点及其与 OS 原理的联系

**多级页表与地址映射。** 分页将虚拟地址空间与物理内存分开管理。本实验通过多级索引定位页表项，将物理页号和权限写入项中。中间级引导遍历，叶子项描述最终映射，两者的合法标志不同。

**引用计数与页面生命周期。** 同一物理页可以被多个地址映射，删除一次映射减少一次引用。最后一次引用消失后才释放。权限更新不增加映射数量，因此引用也应保持不变。

**TLB 与翻译一致性。** CPU 可以缓存地址翻译。修改内存中的页表项后，通过 sfence.vma 使当前 hart 后续采用更新结果，体现软件页表状态与硬件缓存状态的协调。

**失败回滚与资源管理。** 建立页表路径可能需要多次分配。任何一次失败都应回收本次临时资源，避免失败调用持续消耗可用内存。

#### 2. OS 原理中重要但本部分尚未覆盖的知识点

**用户进程与完整生命周期管理。** OS 原理中的进程管理还包括用户态与内核态切换、系统调用、独立地址空间，以及进程阻塞、唤醒、退出和父进程回收等机制。本实验主要完成共享内核地址空间的线程创建和登记，copy_mm 保持占位，do_exit 尚未实现完整退出处理。后续还需建立用户程序运行环境，实现地址空间复制与隔离，并完善进程各状态之间的转换和资源回收。

**按需分页与页面置换。** 完整的虚拟内存管理需要在程序实际访问页面时，通过缺页异常分配物理页、建立映射，并在内存不足时选择页面换出，之后按需换入。这涉及页面置换算法、访存局部性和内存利用率等知识。本实验的页表操作提供了映射建立、权限更新和撤销的基础，当前仍采用预映射方式，尚未实现缺页驱动的按需分配、页面换入换出和写时复制等机制。

**复杂调度、同步互斥与多核并行。** 基础线程切换之外，OS 原理还关注时间片抢占、优先级调度及其公平性，以及共享资源访问中的同步、通信和死锁问题。多核环境还需要跨核保护共享数据，并协调各核的调度与 TLB 状态。本实验主要围绕基础可运行队列和单 hart 下的临界区保护展开，尚未覆盖复杂调度策略、通用同步原语和跨核一致性；当前工程的基础切换仍待模块三接入后联合验证。
