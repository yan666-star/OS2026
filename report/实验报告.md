## 一、实验目的

1. 理解多级页表如何将线性地址关联到物理页，掌握建立映射、更新权限和撤销映射的过程。
2. 理解引用计数与映射数量之间的关系，正确处理同页重复映射、不同页替换和最后一次引用释放。
3. 理解页表更新与 TLB 失效之间的联系，使处理器后续访存使用更新后的翻译。
4. 掌握内存不足时的资源回收方法，保证失败调用不遗留临时页表页。
5. 理解 idle 线程、可运行进程链表与 `current` 指针的关系，掌握在无可运行进程时安全回退到 idle 的方法。
6. 掌握关中断临界区对进程选择、`current` 更新和上下文切换的保护作用，理解单核环境下状态一致性的要求。
7. 理解 Sv39 下 `satp` 切换与 TLB 刷新的时机，以及内核地址在切换前后保持可访问的原因。
8. 掌握汇编层上下文切换与 `forkret` 首次运行链路的衔接，理解「保存 callee-saved 寄存器后 `ret`」为何能同时服务于新建线程和老线程的恢复。

## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线

本部分围绕线性地址、页表项和物理页的对应关系展开。已有分配器提供可用物理页，多级页表遍历函数定位目标项，本模块在此基础上维护具体映射。

建立映射时，需要处理空项、同页映射和异页映射。撤销映射时，需要清除页表项、刷新地址翻译并减少物理页引用。页表项记录映射，引用计数决定物理页能否回收，TLB 影响处理器实际采用的翻译结果，三者必须保持一致。

### 2.2 功能的逐步实现

1. 核对 Lab2、Lab3 依赖，确认物理页分配、地址转换和 Trap 基础可用。
2. 实现映射建立与替换，区分首次映射、同页权限更新和异页替换。
3. 实现幂等删除，处理页表不存在和目标项无效的情况。
4. 完善中间页表分配失败时的回滚，确保已有状态和空闲页数量正确。
5. 运行页表结构检查和实际访存，定位并修正非叶子项权限问题。

### 2.3 进程调度部分的逻辑主线

模块二已经创建并登记了 idleproc 和 initproc，但还没有让 CPU 真正离开 idleproc 的能力。调度部分要闭合「谁来运行 → 如何切过去 → 新线程从哪里开始执行」这条链路：idle 线程发现 `need_resched` 时调用 `schedule()`；调度器在普通进程链表中选出一个可运行进程；`proc_run()` 完成 `current` 更新、页表切换和上下文切换；`switch_to()` 恢复目标线程的栈与返回地址，使新线程从 `forkret` 开始执行。

### 2.4 调度的逐步实现

1. 实现 idle 主体：有待调度请求时进入 `schedule()`，否则用 `wfi` 让 hart 休眠等待中断，不关中断忙等。
2. 实现 `schedule()`：从当前进程在 `proc_list` 中的后继开始环形扫描，跳过链表头，返回第一个 `PROC_RUNNABLE` 进程；找不到时回退到不在链表中的 `idleproc`。
3. 实现 `proc_run()`：在关中断临界区内原子地完成 `current` 更新、`runs` 计数、写 `satp`、刷新 TLB 和 `switch_to`。
4. 实现 `switch_to()`：只保存/恢复 `ra`、`sp` 和 `s0~s11`，不参与调度决策，也不修改 `current` 和页表。
5. 接入首次运行链路：新线程的 `context.ra` 为 `forkret`、`context.sp` 指向 trapframe，因此 `switch_to` 末尾的 `ret` 直接落到 `forkret → forkrets → __trapret → kernel_thread_entry`。
6. 接入本地运行环境并完成联合验证。

### 功能模块一：虚拟内存页操作功能

**负责人**　2411641-薛健

#### 模块功能描述

**需要实现的函数**

```c
int page_insert(pde_t *pgdir, struct Page *page,
                uintptr_t la, uint32_t perm);
void page_remove(pde_t *pgdir, uintptr_t la);
```

**配套调整的函数**

```c
pte_t *get_pte(pde_t *pgdir, uintptr_t la, bool create);
void tlb_invalidate(pde_t *pgdir, uintptr_t la);
static void check_pgdir(void);
```

**功能说明**

本模块为指定线性地址建立或撤销物理页映射，为后续虚拟内存操作提供基础。实现复用现有页表遍历、物理页分配、页表项构造和引用计数接口。

| 场景 | 映射处理 | 引用计数与资源处理 |
|------|----------|------------------|
| 地址未映射 | 写入目标页及请求权限 | 目标页引用加一 |
| 已映射同一物理页 | 更新权限 | 引用计数不变 |
| 已映射其他物理页 | 替换映射 | 新页引用加一，旧页引用减一，归零时释放 |
| 删除有效映射 | 清空页表项并刷新 TLB | 对应页引用减一，归零时释放 |
| 删除不存在的映射 | 直接返回 | 不分配页表，不修改引用计数 |
| 中间页表分配失败 | 返回 -E_NO_MEM | 回收本次临时页，保留原有状态 |

page_insert 先调用 get_pte(pgdir, la, 1)，失败时直接返回 -E_NO_MEM。成功后检查旧项并取得 old_page。仅在新旧页不同时增加目标页引用，随后使用 pte_create(page2ppn(page), perm) 更新页表项并刷新 TLB，最后减少异页旧映射的引用，归零时释放。新项由本次权限重新构造，旧权限不会遗留。

page_remove 调用 get_pte(pgdir, la, 0) 查询已有映射，目标不存在或无效时返回。存在有效映射时，先保存物理页指针，再清空项、刷新 TLB，最后减少引用并按需释放。重复删除时目标项已经无效，因此不会重复回收。

get_pte 在创建新分支时，先用局部变量保存新分支，等两级中间页表分配成功后再发布根项。第二次分配失败时，释放尚未发布的临时页。非叶子项通过 ptd_create 构造。

tlb_invalidate 使用 sfence.vma 刷新当前 hart 对目标地址的翻译，并在内联汇编中增加 "memory" clobber，约束编译器重排相关内存操作。

**实现内容**

**遇到的问题**

隔离运行中，check_alloc_page 和 check_pgdir 已通过，执行 check_boot_pgdir 中向线性地址 0x100 写入字符串时触发 store_page_fault。QEMU 异常日志的故障地址为 0x100。

**本次结果**

### 功能模块二：进程创建及初始化功能

**负责人**　2413777-施骅洋

#### 模块功能描述

**需要实现的函数**

```c
static struct proc_struct *alloc_proc(void);
void proc_init(void);
int kernel_thread(int (*fn)(void *), void *arg, uint32_t clone_flags);
int do_fork(uint32_t clone_flags, uintptr_t stack, struct trapframe *tf);
static void copy_thread(struct proc_struct *proc, uintptr_t esp,
                        struct trapframe *tf);
static int copy_mm(uint32_t clone_flags, struct proc_struct *proc);
```

**功能说明**

本模块负责创建、初始化和登记内核线程。当前执行现场被包装为 idleproc，第一个新建内核线程 initproc 通过独立内核栈和首次运行上下文进入进程管理体系，为后续调度提供可运行实体。

| 函数 | 核心处理 | 返回或完成状态 |
|------|----------|----------------|
| alloc_proc | 分配并清零 PCB，初始化状态、PID、内核页表和链表节点 | 成功返回安全空白 PCB，分配失败返回 NULL |
| proc_init | 初始化管理结构，建立 idleproc，再创建和查找 initproc | current 指向 idleproc，initproc 完成登记并处于 PROC_RUNNABLE |
| kernel_thread | 用临时 trapframe 保存函数入口、参数和特权状态 | 返回 do_fork 的 PID 或负错误码 |
| do_fork | 分配 PCB 和内核栈，构造上下文，分配 PID、登记并唤醒 | 成功返回 PID，失败释放已取得的资源 |
| copy_thread | 将 trapframe 放入新内核栈，设置 context 的首次入口及栈指针 | 为 forkret 首次运行链路准备现场 |
| copy_mm | 保留地址空间处理接口，当前阶段直接返回 0 | 维持内核线程共享内核地址空间的约定 |

alloc_proc 使用 kmalloc 分配 PCB，再通过 memset 清零全部字段，使 parent、mm、tf、context、名称、标志位和调度标记等具有确定的初值。随后设置 state = PROC_UNINIT、pid = -1、pgdir = boot_pgdir_pa，并初始化 list_link 和 hash_link。本工程的内核页表字段名为 pgdir。

proc_init 初始化 proc_list 及各哈希桶后，建立 PID 为 0、状态为 PROC_RUNNABLE 的 idleproc。其 kstack 指向已有 bootstack，need_resched 置为 1，current 指向 idleproc。随后调用 kernel_thread 创建 init_main，通过 find_proc 获取 PID 为 1 的 initproc 并设置名称。按框架约定，idleproc 单独管理且计入 nr_process，普通进程链表和哈希表登记新建线程。因此初始化完成时，nr_process 为 2，普通链表和哈希表各登记一个 initproc。

kernel_thread 清零临时 trapframe，以 s0 保存 fn、s1 保存 arg，将 epc 设置为 kernel_thread_entry，并设置 SSTATUS_SPP、SSTATUS_SPIE，清除 SSTATUS_SIE。随后调用 do_fork(clone_flags | CLONE_VM, 0, &tf)。kernel_thread_entry 从 s1 取参数到 a0，再通过 s0 调用 fn(arg)，函数返回后进入已有 do_exit 路径。

copy_thread 将临时 trapframe 拷贝到新线程内核栈顶，并将副本的 a0 设为 0。传入 esp 为 0 时，采用该 trapframe 地址作为初始栈指针，保证内核线程经 __trapret 恢复后具有有效栈。context 按现有结构体布局内嵌于 PCB，其中 ra 指向 forkret，sp 指向新栈上的 trapframe。后续调度通过 switch_to 恢复 context 后，执行 forkret → forkrets → __trapret → kernel_thread_entry，最终调用 fn(arg)。

do_fork 先检查 MAX_PROCESS 上限，再依次申请 PCB、申请内核栈、处理 copy_mm 并构造首次运行现场。所有可能返回错误的资源准备步骤完成后，才在关中断保护下分配 PID、挂接哈希表与进程链表、增加 nr_process，并调用 wakeup_proc。失败时按“已分配的内核栈 → PCB”的顺序释放。由于错误返回发生在 PID 分配与登记之前，失败路径不会遗留链表节点或增加进程计数。


**涉及文件**

| 文件 | 修改位置 |
|------|----------|
| `kern/process/proc.c` | `//LAB4 function3 2414010` 处实现 `cpu_idle`、`proc_run` |
| `kern/schedule/sched.c` | `//LAB4 function3` 处实现 `schedule` |
| `kern/process/switch.S` | 空文件中实现 `switch_to` 汇编 |

**功能说明**

| 函数 | 核心处理 | 完成状态 |
|------|----------|----------|
| cpu_idle | 检查 `need_resched` 并调度，否则 `wfi` 等待中断 | 不返回的 idle 执行主体，不关中断忙等 |
| schedule | 环形扫描 `proc_list`，选出首个 `PROC_RUNNABLE`，否则回退 `idleproc` | 调用 `proc_run(next)` 完成切换，关中断保护 |
| proc_run | 更新 `current` 与 `runs`，写 Sv39 `satp`，刷新 TLB，调用 `switch_to` | 目标为自身时直接返回；切换原子完成 |
| switch_to | 保存 `ra`、`sp`、`s0~s11` 到 `*from`，从 `*to` 恢复后 `ret` | 不调度、不改 `current`、不改页表 |

cpu_idle 是 idleproc 的执行主体。`current->need_resched` 为真时调用 `schedule()` 让出 CPU；为假时执行 `wfi`，让 hart 在中断到来前保持休眠。它既不关闭中断，也不做空转循环，满足空闲线程的低功耗语义，并保持函数声明中的 `noreturn` 性质。

schedule 的选择策略是从当前进程在 `proc_list` 中的后继开始环形扫描：当 `current == idleproc` 时从链表头开始；扫描跳过链表头 `&proc_list`，遇到第一个 `PROC_RUNNABLE` 即选中。由于 `list_add(&proc_list, elm)` 是尾插，`proc_list` 的顺序就是进程创建顺序，环形扫描天然形成轮转，使每个可运行进程都能获得执行机会，不必再按 `runs` 做二次比较。循环以“重新回到起始节点”为终止条件，保证整圈只遍历一次。若链表为空或没有可运行进程，则显式回退到 `idleproc`——它不挂在 `proc_list` 上，因此不能由扫描得到，也不可能在这里 `panic` 或对空指针解引用。进入调度时清除原进程的 `need_resched`，选中后再清除 `next->need_resched`，表示本次调度请求已被响应；若选中的仍是自身，`proc_run` 直接返回。

proc_run 首先处理 `proc == current` 的退化情况。其余操作全部放在 `local_intr_save` / `local_intr_restore` 组成的临界区内：先记录 `prev = current`，再更新 `current = proc` 并递增 `proc->runs`，随后把目标页表写入 `satp`。写值为 `(uintptr_t)SATP_MODE_SV39 << 60 | (proc->pgdir >> RISCV_PGSHIFT)`，与 `pmm.c` 中 `enable_paging()` 的 `0x8000000000000000 | (boot_pgdir_pa >> 12)` 等价；`pgdir` 和 `boot_pgdir_pa` 都是物理地址，不使用 Sv32 遗留的 `lsatp()`。写完 `satp` 立即调用 `flush_tlb()`：RISC-V 并不保证写 `satp` 会清除旧的翻译缓存，而本工程没有使用 ASID，不刷新就可能让新进程命中旧进程的 TLB 项。最后调用 `switch_to(&prev->context, &proc->context)`。恢复执行后各自用自己内核栈上的 `intr_flag` 恢复中断，因此嵌套在 `schedule()` 的临界区中是安全的。

switch_to 是纯汇编上下文切换。它按 `struct context` 的布局（每项 8 字节）把 `ra`、`sp` 和 `s0~s11` 存入 `*from`，再从 `*to` 恢复这些寄存器，最后 `ret`。调用者保存的 `t0~t6`、`a0~a7` 按 RISC-V 调用约定在调用点已不需要保留，故不入栈。它不做调度决策，不修改 `current`，也不修改页表。首次运行时，`copy_thread` 已把 `context.ra` 设为 `forkret`、`context.sp` 指向 trapframe，因此 `ret` 直接落到 `forkret`，再经 `forkrets → __trapret → sret → kernel_thread_entry` 进入线程函数，不需要额外跳转或手工修改上下文。

5. 本地运行问题先定位到 OpenSBI 下一跳地址和开分页后的取指映射，再按前序 lab 的方案做最小环境适配，不把运行配置问题混入内核算法。

### Challenge：RISC-V 中断状态控制与多级页表查询机制分析

**负责人：** 2414010-严子涵

#### 1. `local_intr_save` / `local_intr_restore` 如何实现开关中断

这两个宏定义在 `kern/sync/sync.h`，底层是 CSR `sstatus` 的 `SIE` 位（Supervisor Interrupt Enable）：

```c
static inline bool __intr_save(void) {
    if (read_csr(sstatus) & SSTATUS_SIE) {
        intr_disable();
        return 1;
    }
    return 0;
}
static inline void __intr_restore(bool flag) {
    if (flag) { intr_enable(); }
}
#define local_intr_save(x)   do { x = __intr_save(); } while (0)
#define local_intr_restore(x) __intr_restore(x);
```

`intr_enable()` / `intr_disable()` 在 `kern/driver/intr.c` 中分别执行 `set_csr(sstatus, SSTATUS_SIE)` 和 `clear_csr(sstatus, SSTATUS_SIE)`；`riscv.h` 把这两个操作展开成单条 `csrrs` / `csrrc` 指令，因此对当前 hart 是原子的读改写。

执行过程可以分成两步：

1. `local_intr_save(intr_flag)` 先读 `sstatus`：若进入临界区前中断是开的，则关中断并把 `intr_flag` 记为 1；若本来就是关的，则不做任何修改并把 `intr_flag` 记为 0。
2. `local_intr_restore(intr_flag)` 只在 `intr_flag == 1` 时重新开中断，也就是**恢复到进入前的状态**，而不是无条件开中断。

保存旧状态而不是直接开关，是为了支持嵌套临界区。以本实验模块三为例：`schedule()` 外层 `local_intr_save` 得到 1、关中断；它调用的 `proc_run()` 内层再保存时得到 0、不再改动；内层恢复时发现标志为 0 什么都不做，直到外层恢复才真正开中断。若内层无条件开中断，外层的调度原子性就会被破坏。

需要注意，`SIE` 只控制当前 hart 的 S 态中断使能：它不屏蔽 M 态中断，也不影响其他 hart；已经 pending 的中断不会丢失，只是延迟到重新使能后再投递。这也解释了为什么 `cpu_idle` 不能在关中断状态下执行 `wfi`：那样 hart 不会被可屏蔽中断唤醒，也无法响应调度请求。

#### 2. 不同分页模式的工作原理，以及 `get_pte()` 两段代码为何相像

**（a）三种模式的共同点与差异**

Sv32、Sv39、Sv48 都是「固定位宽的层次化 radix 页表」：线性地址 = 若干级 VPN 索引 + 页内偏移；每级页表占一页，按 VPN 索引取项；表项保存下一级（或最终物理页）的页帧号和权限位；从 `satp.PPN` 指向的根表开始逐级索引，遇到叶子项就得到物理地址，遇到无效项或缺权限就触发缺页异常。

| 项目 | Sv32 | Sv39 | Sv48 |
|------|------|------|------|
| 级数 | 2 | 3 | 4 |
| 线性地址位数 | 32 | 39 | 48 |
| 每级 VPN 索引位数 | 10 | 9 | 9 |
| 每级页表项数 | 1024 | 512 | 512 |
| PTE 宽度 | 4 字节 | 8 字节 | 8 字节 |
| `satp.MODE` | 1 | 8 | 9 |
| 大页 | 4 MiB | 2 MiB / 1 GiB | 2 MiB / 1 GiB（多一级索引） |

本工程的 `kern/mm/mmu.h` 实际采用 Sv39 形态：`PDX1(la)`、`PDX0(la)`、`PTX(la)` 各取 9 位（移位 30/21/12，掩码 `0x1FF`），`NPDEENTRY`/`NPTEENTRY` 均为 512，`PTE_ADDR` 屏蔽低 10 位标志后得到下一级表的物理基址，再用 `KADDR` 转成内核虚拟地址。文件开头关于 Sv32 的注释是历史遗留描述，与现有宏定义不一致，应以宏为准。

**（b）两段代码相像的原因**

`get_pte()` 中两段代码分别处理第一级 `pdep1` 和第二级 `pdep0`，它们的模式完全相同：

1. 读取当前级的表项，检查 `PTE_V`；
2. 若无效且 `create == true`，分配一页、清零、用 `ptd_create` 构造只带 V 的非叶子项；
3. 若无效且不能创建，返回 `NULL`；
4. 用 `PDE_ADDR(entry)` 取得下一级表的物理基址，继续下一级；失败时释放刚分配的临时页。

这种重复来自分页机制本身：**每一级的「查项—缺失则建表—写入非叶子项—下降一级」是同一个操作**，级数变化只会让这段代码重复更多次，而不改变它的结构。Sv32 比 Sv39 少一级，Sv48 比 Sv39 多一级（需要再增加一段取 `PDX2` 的同构代码），差别集中在索引位数、PTE 宽度和 `satp.MODE`，不在遍历算法。因此两段代码相像并不是复制粘贴的偶然，而是层次页表均匀性的直接反映。

本实现只走两级，是因为启动页表在最高级放了 1 GiB 大页（`entry.S` 中第 511 项），`get_pte()` 面对的是「2 MiB 中间级 + 4 KiB 叶子级」两层的遍历需求；非叶子项用 `ptd_create` 构造，保持 Sv39 保留位为 0，这也是模块一实际访存出错后修正的点。需要注意，该实现假定中间项都指向页表；若遇到 1 GiB/2 MiB 叶子大页，它已经是最终映射，不能再按表索引下降，这段代码并未处理该情形。

#### 3. 查找与分配合并在一个函数里是否合适

**优点是调用方简单、遍历只做一次。** `page_insert` 和 `page_remove` 都只需要一个「给我这个地址对应的 PTE 指针」的接口，`create` 参数区分只读查找和缺项创建；索引计算、PTE 构造和缺项错误路径集中在一处，避免每个调用者重复实现多级下降。在单 hart、无抢占的教学内核里，这种集中写法也更容易保证「失败时回滚到原状态」这一不变量。

**缺点是职责混杂、失败语义和回滚成本高。** 函数名是 `get`，却可能分配页、改引用计数、修改上级页表；返回 `NULL` 既可能表示「未映射」也可能表示「分配失败」，调用者必须自行区分。函数内部有两个分配点和一套回滚逻辑：第一级分配成功而第二级失败时，必须释放临时页并且不能发布根项——模块一第一次迭代正是踩到这个点后才补上回滚。若以后引入抢占或多核，「先查后建」必须作为一个原子事务，合并写法要求调用方自己清楚它持有什么锁，接口语义并不显式。

**结论：在当前实验范围内可以接受，但不宜作为通用接口继续扩展。** 本工程调用点少、单 hart 顺序执行，合并写法与 uCore 原有 API 一致，收益大于成本。若要扩展到更复杂场景，更稳妥的做法是拆成纯查找 `find_pte(pgdir, la)` 与带分配的 `get_pte(pgdir, la, create)` 包装，把「逐级分配 + 失败回滚 + 最后发布根项」封装成内部 helper，并通过返回错误码区分「不存在」和 `-E_NO_MEM`；无论拆不拆，都必须维持已有不变量：失败不泄漏页、非叶子项标志合法、发布顺序正确，以及与 TLB 状态一致。

## 六、实验总结与收获

### 对操作系统的理解

#### 1. 本实验的重要知识点及其与 OS 原理的联系

**多级页表与地址映射。** 分页将虚拟地址空间与物理内存分开管理。本实验通过多级索引定位页表项，将物理页号和权限写入项中。中间级引导遍历，叶子项描述最终映射，两者的合法标志不同。

**引用计数与页面生命周期。** 同一物理页可以被多个地址映射，删除一次映射减少一次引用。最后一次引用消失后才释放。权限更新不增加映射数量，因此引用也应保持不变。

**TLB 与翻译一致性。** CPU 可以缓存地址翻译。修改内存中的页表项后，通过 sfence.vma 使当前 hart 后续采用更新结果，体现软件页表状态与硬件缓存状态的协调。

**失败回滚与资源管理。** 建立页表路径可能需要多次分配。任何一次失败都应回收本次临时资源，避免失败调用持续消耗可用内存。

**进程调度与现场保存。** 调度并不只是选一个进程：选中之后必须原子地更新当前进程、地址空间和寄存器现场，否则中断可能在中间状态切入。idle 线程是调度器没有候选者时的安全落点；关中断临界区保证了单核上的状态一致性；而 `satp` 切换后刷新 TLB，体现了软件维护的页表与硬件翻译缓存之间必须协调。上下文切换只保存 callee-saved 寄存器，既遵守调用约定，也让新建线程和老线程复用同一条 `ret` 返回路径。

#### 2. OS 原理中重要但本部分尚未覆盖的知识点

**用户进程与完整生命周期管理。** OS 原理中的进程管理还包括用户态与内核态切换、系统调用、独立地址空间，以及进程阻塞、唤醒、退出和父进程回收等机制。本实验主要完成共享内核地址空间的线程创建和登记，copy_mm 保持占位，do_exit 尚未实现完整退出处理。后续还需建立用户程序运行环境，实现地址空间复制与隔离，并完善进程各状态之间的转换和资源回收。

**按需分页与页面置换。** 完整的虚拟内存管理需要在程序实际访问页面时，通过缺页异常分配物理页、建立映射，并在内存不足时选择页面换出，之后按需换入。这涉及页面置换算法、访存局部性和内存利用率等知识。本实验的页表操作提供了映射建立、权限更新和撤销的基础，当前仍采用预映射方式，尚未实现缺页驱动的按需分配、页面换入换出和写时复制等机制。

**复杂调度、同步互斥与多核并行。** 基础线程切换之外，OS 原理还关注时间片抢占、优先级调度及其公平性，以及共享资源访问中的同步、通信和死锁问题。多核环境还需要跨核保护共享数据，并协调各核的调度与 TLB 状态。本实验主要围绕基础可运行队列和单 hart 下的临界区保护展开，尚未覆盖复杂调度策略、通用同步原语和跨核一致性；模块三已完成基础切换，并通过两个测试线程的联合验证，但仍是协作式轮转，没有时间片抢占和优先级调度。

### AI 协作开发的经验

模块三实现过程中，先让 AI 阅读 `proc.h`、`switch.S`、`test_lab4.c` 和 `pmm.c` 的实际定义，再按「调度策略、原子性、页表切换、首次运行链路」四部分提出明确约束，避免只按通用 ucore 模板生成代码。对本机 GCC、QEMU 与评分脚本不一致的问题，要求 AI 先给出可观测证据（OpenSBI 的 `Next Address`、QEMU 的 `exec_page_fault` 日志、评分脚本的缺失字符串）再修改，因而把内核算法问题与运行环境问题区分开来。验证结果也反过来修正了两处描述：模块二遗留的问候串与评分检查不一致，以及本地工具链把测试文件的函数指针类型不兼容视为错误；两处都做了最小范围处理并在报告中记录。
